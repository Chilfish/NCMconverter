# 009 — 空值标签被写入

## 摘要

`WriteTags` 早期**无条件**写入每个字段，于是产生了三类产物污染：写入空的标题、把曲目名误当专辑名写、以及嵌入一个空的封面帧。正确行为是：字段为空就**跳过**，不产生空帧；封面为空时按「下载 → 降级为链接 → 都不做」三级处理。

## 影响

- 产物里出现空标题帧、错误的专辑值、空 `APIC` 帧。
- 播放器可能显示空白字段，或把空帧当有效元数据处理。

## 根因分析（blameless）

- **Why 会写入空值？** 代码对每个字段都直接调用 setter，没有「有值才写」的判定。
- **Why 曲名会当专辑？** 缺少专辑时有一处回退把曲目名填了过去，属于「想给个默认值」的错误意图。
- **Why 空封面也会嵌？** 封面路径没有区分「容器内没有封面」与「有封面但为空」。
- **Why 测试要逐个断言「没被调用」？** 只断言「写了正确字段」抓不到「额外写了空字段」。

**贡献因素**：setter 被当作幂等无害调用；缺少「缺省字段不该出现在产物里」的显式约定。

## 做得对的地方

- 修复后约定明确：**空值跳过**；`writeCover` 三级策略（内嵌 → 下载 → 存链接）。
- 测试用 fake tagger **逐字段断言是否被调用**，同时锁住「空值不写」与「非空才写」两侧。

## 教训

标签字段为空时要跳过（不写空标题、不把曲名当专辑、不嵌空封面）；测试要断言「缺省字段根本没被写入」，而不只是「正确字段被写入」。
