# 002 — 容器魔法校验用了 and 组合

## 摘要

`.ncm` 的魔数是两个 `uint32`（ASCII `CTEN` 与 `FDAM`）。校验时若把它们用一个布尔表达式**错误地组合**，只损坏其中一个魔数仍会通过校验。正确行为是：任一魔数不符即拒绝。

## 影响

- 一个损坏或不完整的文件可能被当成合法容器继续解析，把错误推迟到更深处、报出更难归因的错。
- 不会损坏用户数据，但会降低错误信息的可诊断性。

## 根因分析（blameless）

- **Why 会放行？** 校验逻辑对两个魔数的组合用错了布尔运算，导致「只坏一个」的情形不触发拒绝。
- **Why 没被发现？** 手测通常用完全损坏的文件（两个魔数都坏），两个条件是「都假」还是「一真一假」在肉眼层面看不出差别。
- **Why 测试要逐个损坏？** 只有**分别**只损坏第一个和第二个魔数，才能把这类组合错误逼出来。

**贡献因素**：魔数被拆成两个常量、二者语义对称，容易想当然地一起判断。

## 做得对的地方

- 修复后测试**逐个**损坏两个魔数（`index: 0` 与 `index: 4`），而不是只测完全损坏的输入。
