# 011 — 端到端测试在 fixture 缺失时空跑报绿

## 摘要

真实 fixture 的端到端测试需要一个存在于 `testdata/` 的 `.ncm`。早期实现里，当 `testdata/` **没有匹配的容器时测试会 `Skip`**——于是「夹具不在」被当成了「无需测试」，门禁显示全绿，而实际什么行为都没验证。正确行为是区分两种情况：目录**不存在**才 `Skip`（夹具在模块之外），目录存在但**没有容器则 `Fatal`**。

## 影响

- **门禁诚信**：端到端检查可以永远不运行而仍报绿。
- 一个「看起来被覆盖」的路径（真实文件转换 + 标签 + 音频完整性）实际上零覆盖。

## 根因分析（blameless）

- **Why 报绿？** `testdata/` 里没有 `.ncm` 时走了 `Skip` 分支。
- **Why 会 Skip？** 原始意图是「夹具可能在模块外，缺失时优雅跳过」，但把「目录为空」也归入了同一分支。
- **Why 要区分？** 「夹具不在模块里」是合理的环境差异；「目录在但为空」意味着端到端检查根本没跑——这是必须报警的状态。
- **Why 需要显式守卫？** Go 的 `Skip` 与「通过」在汇总里同样是绿，容易被忽略。

**贡献因素**：`Skip` 被用作「无素材」的通用兜底，没有区分「环境不允许」与「配置错误」。

## 做得对的地方

- 修复用一条清晰的分支表达两种语义：`fs.ErrNotExist` → `Skipf`；否则 `Glob` 到 0 个 → `Fatalf("... would not run")`。
- 这与 [`../engineering/testing.md`](../engineering/testing.md) 的「改坏被测行为它会红吗」可证伪性原则一致。
