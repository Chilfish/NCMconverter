# 006 — 多位艺人只剩最后一位

## 摘要

写 mp3 标签时，若对每个艺人名依次调用 `id3v2.SetArtist`，只有**最后一个**会留下——因为 `SetArtist` 是**替换**整个 `TPE1` 帧，不是追加。正确做法是把名字连接成一个值（`"; "`）一次性写入，这与 Vorbis comment（flac）允许每个名字一个条目的语义不同。

## 影响

- 合作曲目的艺人信息不完整，只保留最后一位。
- 静默错误：转换成功，标签看似存在，只是内容缺失。

## 根因分析（blameless）

- **Why 只剩一个？** `SetArtist` 的语义是「设置」（替换帧），不是「添加」。
- **Why 会逐个调用？** 数据模型里艺人是数组，直觉上会循环写入。
- **Why 语义会不同？** mp3 的 `TPE1` 是单值文本帧，而 flac 的 Vorbis comment 支持同名多值——两个格式的「多艺人」表达方式本就不同，容易混淆。
- **Why 测试要断言全量？** 只断言「有艺人帧」会漏掉「只剩一个」。

**贡献因素**：库 API 的隐式替换语义；mp3 与 flac 对多艺人建模不一致。

## 做得对的地方

- 修复后两处**各自贴合格式语义**：mp3 用 `"; "` 连接成单值；flac 每条名字一个 `ARTIST` 条目。
- 测试断言的是**连接后的完整值**，能同时抓住「丢了」和「顺序/连接符错了」。

## 教训

标签库的 `Set*` 多是替换语义：多值字段要一次性写入（mp3 连接成单值），别逐个调用；改前先确认格式本身如何表达多值。
