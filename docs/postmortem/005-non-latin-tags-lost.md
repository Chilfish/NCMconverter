# 005 — 非拉丁标签丢失

## 摘要

容器里的音频常常自带一个 **ID3v2.3** 标签。ID3v2.3 的默认文本编码是 ISO-8859-1，无法表示任何非拉丁文标题或艺人。若打标签时**不顶掉版本**，中文/日文的标题、专辑、艺人、歌词会直接丢字或乱码。对策是把 mp3 标签固定写到 **ID3v2.4 + UTF-8**。

## 影响

- 中日文曲目的标题/专辑/艺人/歌词全部无法正确显示。
- 对以中文/日文曲库为主的用户，等于标签功能失效。

## 根因分析（blameless）

- **Why 文本丢失？** 写入沿用了源文件标签的版本（v2.3），其默认编码表达不了非拉丁字符。
- **Why 会沿用？** 标签库打开已有标签时默认保持其版本，除非显式设置。
- **Why 需要显式顶掉？** 本工具的场景恰恰是「源文件带旧标签 + 元数据是中日文」，两者叠加必然触发。
- **Why 测试要写非拉丁？** 只用 ASCII 名字测试，任何编码都能通过，永远发现不了。

**贡献因素**：标签库的默认行为、源文件的旧版本、测试数据的字符集选择。

## 做得对的地方

- 修复方案是**显式且集中**的：`mp3.New` 打开后立刻 `tag.SetVersion(4)`，所有文本帧显式 `EncodingUTF8`。
- 测试刻意使用非拉丁字符串（`結束バンド`、`ドッペルゲンガー`），把编码问题暴露在测试层。
