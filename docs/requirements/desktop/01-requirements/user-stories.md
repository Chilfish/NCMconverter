# 用户故事：桌面应用

> 关联：[PRD.md](PRD.md)｜[../04-testing/test-plan.md](../04-testing/test-plan.md)
> 每个故事给出「作为…我要…以便…」与可判定的验收点；编号 `US-n`，与 PRD 的 `FR-n` 对应。

## 角色

| 角色 | 说明 |
| --- | --- |
| **普通用户** | 不懂命令行，手里有一批 `.ncm`，只想听歌 |
| **整理者** | 熟悉工具，关心命名规则、去重、目录结构 |
| **脚本用户** | 在 shell/CI 里调用，关心行为稳定与退出码 |
| **开发者** | 维护这个仓库，关心改动是否可测、可发布 |

---

## US-1 双击即用（普通用户）

> 作为普通用户，我要双击这个程序就能看到窗口，以便不用学命令行。

- 无参数启动出现窗口，标题为 `NCMconverter`。
- 窗口内有「添加文件/添加文件夹」按钮，以及拖拽提示。
- 首次打开无任何报错弹窗。

对应：FR-1.1、FR-2.1、FR-2.2、FR-5.3。

## US-2 拖进来就能转（普通用户）

> 作为普通用户，我要把文件或整个文件夹拖进窗口，以便一次性处理一批。

- 拖入目录后，队列显示该目录；统计行显示将被处理的 `.ncm` 数量。
- 统计数量与 `ncmconverter --dry-run -d <depth> <dir>` 列出的数量**一致**。
- 拖入重复路径不会产生重复条目。

对应：FR-2.3、FR-2.5。

## US-3 看得到进度（普通用户）

> 作为普通用户，我要看到每个文件转好了没有，以便知道还剩多少、有没有出问题。

- 每完成一个容器，日志区出现一行：`源文件 → 目标文件`，带「已转换/已跳过/失败」标签。
- 进度条随处理数量推进；结束时给出「共 N 个 · 转换 X · 跳过 Y · 失败 Z · 耗时」。
- 失败行显示原因，且**其余文件继续转换**。

对应：FR-4.2、FR-4.3、FR-4.5、FR-4.6。

## US-4 中途取消（普通用户）

> 作为普通用户，我要能中途停止，以便发现选错目录时不用等它跑完。

- 运行中「取消」按钮可见且可用；点击后：
  - 不再开始新的文件；
  - 已经写出的产物保留；
  - 汇总显示「已取消」并带上已完成的数量；
  - 界面回到可操作状态（可直接再跑一次）。

对应：FR-4.4、FR-4.5。

## US-5 按规则命名并跳过重复（整理者）

> 作为整理者，我要按「艺人 - 标题」命名并跳过已转换过的文件，以便增量整理曲库。

- 模板输入框接受 `{artist} - {title}` 等占位符；界面提供占位符说明。
- 勾选「跳过已存在的文件」后，目标已存在时**不覆盖**，并在日志中标记「已跳过」。
- 模板产生非法路径（含分隔符/试图越出输出目录）时，报错而不是写到别处。

对应：FR-3.1、FR-3.2、FR-3.5。

## US-6 先预览再动手（整理者）

> 作为整理者，我要先看会转换哪些文件，以便确认范围再执行。

- 勾选「试运行（只列出，不写入）」后运行：日志逐条列出「将转换」，**磁盘上不产生任何文件**，也不创建输出目录。
- 汇总显示总数与「试运行」。

对应：FR-3.5、FR-4.3。

## US-7 脚本行为不变（脚本用户）

> 作为脚本用户，我要保证命令行调用和退出码完全没变，以便现有脚本继续可用。

- `ncmconverter --help`、`--version`、`-d/-o/-n/-t/-q/--dry-run/--skip-existing/--output-template` 的行为、默认值、日志文案与退出码与本次改动前一致。
- 只要带参数（除 `MYGO_GENERATE` 生成客户端的情形）就走 CLI，不会弹窗。
- Windows：从终端调用时输出可见（父控制台已附加）。

对应：FR-1.1、FR-1.2、FR-1.4。

## US-8 开发体验（开发者）

> 作为开发者，我要能热更新地改前端，并且类型与 Go 代码同源，以便少写错、少调试。

- `bun run dev` 启动开发应用，改前端即时生效。
- 改 Go 的绑定方法/事件后，`bun run generate` 更新 `desktop/src/mygo.ts`；类型检查能发现调用不一致。
- CI 校验 `desktop/src/mygo.ts` 与 Go 代码同步，防止漂移。

对应：NFR-3、AC-8。

## US-9 可发布（开发者）

> 作为维护者，我要 tag 之后自动出三平台安装包，以便用户能装上。

- tag 触发发布 workflow；macOS 出 dmg/`.app`，Windows 出 exe + 安装器，Linux 出 tar.gz + deb。
- 缺签名密钥时不阻塞（ad-hoc 签名），有密钥时启用签名/公证。
- 产物挂在对应 tag 的 Release 上。

对应：FR-5（发布不属界面）、NFR-6、AC-9、AC-10。
