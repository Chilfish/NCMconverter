## 问题项

### P2-1 覆盖率只有上传、没有阈值

- **位置**：`.github/workflows/ci.yml`（`coverage` job）。
- **现状**：`make coverage` 产出 `coverage.out` 并上传 artifact，但没有最低覆盖率门槛。
- **建议**：评估引入阈值或 codecov；至少让覆盖率退化可见。
- **去向**：[`../planning/backlog.md`](../planning/backlog.md)（`[hardening]`）。

### P2-2 测试 fixture 的版权与体积

- **位置**：`testdata/Ave Mujica - KINGS (Cover).ncm`（约 5.3MB）与同名 `.lrc`。
- **现状**：商业歌曲翻唱，经 `.gitignore` 的 `!testdata/*` 例外进入公开仓库。
- **建议**：发布前确认可接受，或改为 CI 按需下载 / 让相关测试跳过。
- **去向**：[`../planning/backlog.md`](../planning/backlog.md)。

### P2-3 `reserved` 字段语义未证实

- **位置**：`internal/ncm/ncm.go`（`metaEnd+5`，实测等于 cover 长度）。
- **现状**：不读取；若格式变化，这里会错位。
- **建议**：找更多样本比对后再决定是否校验。
- **去向**：[`../planning/backlog.md`](../planning/backlog.md)。

### P2-4 上游库的句柄与临时文件风险

- **位置**：`go-flac` 的 `ParseFile`（句柄泄漏）、`id3v2` 的 `Save`（临时文件残留）。
- **现状**：均已本地绕开；`TestRunLeavesNoTemporaryFiles` 作为行为防线。
- **建议**：向上游反馈；升级依赖前重读注释。
- **去向**：[postmortem 012](../postmortem/012-upstream-contract-traps.md)（状态 Active）。

### P3-1 `meta.Comment` 会把原始 meta 段写进产物的 comment 字段

- **位置**：`internal/tag/tag.go` 的 `SetComment(meta.Comment)`。
- **现状**：这是**刻意的**——原始 meta 段用于标识来源文件；但内容较长且不经清洗。
- **建议**：确认是否是期望行为；若是，在 `features/tagging/tag.md` 与 README 里说明。

### P3-2 `--output-template` 渲染为空时回退源名

- **位置**：`internal/app/convert.go` 的 `outputPath`。
- **现状**：模板字段缺省（如 `{artist}` 无艺人）导致整串为空时回退源文件名（已测）。
- **建议**：保留该行为，但在 README 的模板说明里点明。

### P3-3 `--depth 0` 的语义变更属破坏性

- **位置**：`internal/app/app.go` 的 `findNCM`。
- **现状**：旧行为「什么都不做」→ 新行为「只处理直接子文件」，已写入 `CHANGELOG.md`。
- **建议**：作为首个发布版本的破坏性变更在 Release 说明里再次强调。
