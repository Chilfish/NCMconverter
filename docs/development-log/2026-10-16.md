## 复用层：`internal/app` 暴露 `Scan` 与 `OnFile`（提交 ①，`refactor:`，✅ 已完成）

**背景**：`app.Run` 只把每文件结果写进 `slog`，桌面拿不到结构化进度；还需要一个「开跑前展示工作量」的入口。

**实现**：新增 `internal/app/report.go`（`Outcome` 常量 + `FileResult`）；`Options` 增加 `OnFile func(FileResult)`（**在既有互斥锁内**调用，天然串行）；`collect` → 导出 `Scan`（同一实现、同一行为，只改名 + 补文档注释）；`convert` 改为返回 `(FileResult, error)`，在算出 `outputPath` 后填 `Dest`。既有 `slog` 调用与 `Run` 签名不变——[ADR-010](../planning/architecture.md)、[features/cli](../features/cli/cli-and-orchestration.md)。

**验证**：`report_test.go` 锁定试运行/成功/跳过/失败四种回调与「无回调时行为不变」；`app_test.go` 两处调用点改名。行为不变，CLI 输出、参数与退出码不动。

**文档**：[features/cli/cli-and-orchestration.md](../features/cli/cli-and-orchestration.md)（`Scan`/`OnFile`）、CHANGELOG。

## 桌面应用：`internal/desktop` + 双模式入口 + 前端（提交 ②，`feat:`，✅ 已完成）

**实现**：`cmd/ncmconverter/main.go` 改为双模式分支（无参数 → `desktop.Run()`；有参数 → `runCLI()`；带 `MYGO_GENERATE` 走桌面分支以生成客户端）；新增 Windows 控制台垫片 `console_windows.go`（`AttachConsole`，仅标准库 `syscall`，不引入 cgo）与空实现 `console_other.go`；`internal/desktop`（`service.go` 绑定服务 + `app.go` 装配，全部指针接收者）导入 mygo；`desktop/` 为 web 前端，`mygo.config.ts`/`package.json`/`tsconfig.json`/`vite.config.ts` 放在仓库根（Vite `root: "desktop"`），`desktop/src/mygo.ts` 由 `mygo generate` 生成并提交——[ADR-010](../planning/architecture.md)、[design](../requirements/desktop/02-design/architecture.md)。

**验证**：`internal/desktop/service_test.go` 用 `ncmtest` 造容器、以零值 `mygo.Channel` 直调 `Converter.Run`（**不需要窗口**），覆盖计数、失败不升级为聚合错误、单飞、取消归一、`Scan` 与 `Run` 一致、threads 校验透传。`bun run typecheck` 与 `make desktop` 在 CI 三平台跑。

**文档**：[features/desktop/desktop-app.md](../features/desktop/desktop-app.md)、[requirements/desktop/](../requirements/desktop/)。
